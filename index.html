Scenario Optimizer

Search for the best solar & battery size — settings and results, side by side

Each candidate size runs its own Monte Carlo simulation of load-shed variability, exactly like the diagnostics above — so the recommendation already accounts for good days and bad days, not just one lucky draw.
Optimize for
Net Savings % weighs the monthly share against the bill, so it can favor a smaller, cheaper system. Bill Savings PKR/month ignores that cost and only measures the utility/genset-side reduction, so it tends to favor the largest system available. Worth checking both.
Confidence level (how the load-shed variability lever gets read)
P50 is the median outcome across simulated draws. P90 is the conservative end — a value the simulation clears 9 times out of 10, so it's a safer number to size against if you'd rather under-promise.
Search precision (Monte Carlo iterations per candidate)
Seasonal variation
With this on, each candidate is evaluated once per month using that month's seasonal solar/load factor, not just one repeated day. This tends to pull the recommended size up slightly and push it toward more battery, since the optimizer can no longer "hide" a winter shortfall behind a good summer average — it costs more search time (12× the simulated days per candidate) in exchange for a sizing that holds up year-round, not just on the day it was tested against.
Minimum net savings (constraint, not the objective)
Filters out any candidate whose median Net Savings % falls outside this band — applies regardless of which objective above you're ranking by, so you can chase max Bill Savings while still ruling out sizes that don't clear a savings bar.
